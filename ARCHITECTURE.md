# Jutsu Studio for Windows and Linux: architecture

A Tauri 2 port of the macOS app [jutsuhq/jutsu-studio](https://github.com/jutsuhq/jutsu-studio), whose `ARCHITECTURE.md` and `docs/features.md` describe
the behavior this app reproduces. This document fixes the layout here and what replaces each Apple framework.

## Baseline

| Decision | Choice |
|---|---|
| Shell | Tauri 2.x (stable line), one main window, system tray |
| Logic | Rust 2024 workspace, tokio |
| UI | React 19, TypeScript, Vite, Tailwind 4, TanStack Query and Router, Zustand |
| IPC | Commands for request and response, `tauri::ipc::Channel` for progress, events for "something changed"; bindings generated by `tauri-specta` |
| Storage | SQLite through `sqlx` (WAL, migrations), files on disk, the OS credential store through `keyring` |
| Networking | `reqwest` with rustls |
| Media | LGPL `ffmpeg` and `ffprobe` as bundled sidecars |
| Playback | A loopback HTTP server (`axum`, 127.0.0.1, random port, per-session token, Range support) serves files to `<video>` |
| Packaging | NSIS on Windows; deb, rpm and AppImage on Linux |

## Layout

```
Cargo.toml                 workspace, shared lints and dependency versions
crates/
  jutsu-core/              pure domain: models, pricing, validation, budget, job state machine, ports. No I/O
  higgsfield/              Higgsfield clients with no app types: `core` (errors, transport), `api` (REST, API key),
                           `mcp` (OAuth 2.1 + PKCE, MCP Streamable HTTP client, the account's tools as typed calls)
  jutsu-providers/         both connections as `GenerationProvider`s over `higgsfield`
  jutsu-store/             SQLite: jobs, materials, assets, templates, delivery sets; file layout; JSON ledgers
  jutsu-media/             ffmpeg pipeline: probe, trim, transcode, thumbnails, frames, audio, export, on-device engines
  jutsu-engine/            the job engine: queue, slots, polling, downloads, resume, agent spending guard
  jutsu-agent/             the agent socket: wire types, framing, listener, client, inbox
  jutsu-mcp/               the MCP server the helper runs: JSON-RPC over stdio, tools
  jutsu-cli/               the `jutsu` helper binary (`jutsu mcp`), bundled next to the app
  jutsu-app/               UI logic without UI: connection store, form models, view models, messages, services
src-tauri/                 the adapter: commands, events, tray, notifications, plugins, media server wiring
src/                       the React app
  design/                  tokens and shared controls
  features/<name>/         one folder per screen: create, queue, library, settings, onboarding, templates, compare, agents
  bindings.ts              generated
```

Dependency direction: `src-tauri` → `jutsu-app` → `jutsu-engine`, `jutsu-store`, `jutsu-media`,
`jutsu-providers`, `jutsu-agent` → `jutsu-core`. `higgsfield` imports nothing of the app. `jutsu-cli` →
`jutsu-mcp` → `jutsu-agent`. Nothing but `src-tauri` depends on `tauri`.

## Swift module → here

| macOS | Here |
|---|---|
| `JutsuCore` | `crates/jutsu-core` (with `models.json`, `pricing.json` copied unchanged) |
| `HiggsfieldKit` (`HiggsfieldCore`, `HiggsfieldAPI`, `HiggsfieldMCP`) | `crates/higgsfield` |
| `HiggsfieldProviders` | `crates/jutsu-providers` |
| `Persistence` (SwiftData) | `crates/jutsu-store` (SQLite; each record keeps the value as JSON plus the columns queries filter and sort on, as `JobRecord` does) |
| `MediaKit` (AVFoundation, VideoToolbox, Speech) | `crates/jutsu-media` (ffmpeg; see On-device engines) |
| `JobEngine` | `crates/jutsu-engine` |
| `Secrets` (Keychain) | `keyring` behind the `CredentialVault` port, implemented in `jutsu-app` |
| `Presentation` | `crates/jutsu-app` for rules, models and services; pure display formatting may live in `src/` |
| `JutsuAgent`, `JutsuMCP`, `JutsuCLI` | `crates/jutsu-agent`, `crates/jutsu-mcp`, `crates/jutsu-cli` |
| App target (SwiftUI views) | `src/features/*`, `src/design/*` |
| App target (`System/`: menu bar, Dock, notifications, updater) | `src-tauri` (tray, notifications, single instance, autostart, updater) |

## Platform replacements

| macOS | Windows and Linux |
|---|---|
| Keychain | Windows Credential Manager, Secret Service; service `com.jutsustudio.desktop.connection` |
| `~/Movies/Jutsu Studio/{Videos,Images}` | the user's Videos folder: `<Videos>/Jutsu Studio/{Videos,Images}` |
| Application Support container | the app data dir (`%APPDATA%`, `$XDG_DATA_HOME`) with the same file names |
| Security-scoped bookmarks | plain paths |
| `MenuBarExtra` panel | tray icon with a menu, and a small undecorated panel window for the rich panel |
| Dock badge and Dock menu | taskbar overlay and progress where the platform has one; the tray menu |
| `UserNotifications` with actions | native notifications; actions where the platform supports them, else a click opens the job |
| Sparkle | `tauri-plugin-updater` against GitHub releases |
| `SMAppService` login item | `tauri-plugin-autostart` |
| App group socket `agent.sock` | a named pipe on Windows, a Unix socket in the runtime dir on Linux (`interprocess`) |
| Finder, Quick Look, Trash | the file manager through `opener`, an in-app preview, the `trash` crate |
| `NWPathMonitor` | a connectivity probe behind the `Connectivity` port |
| OAuth loopback (Network.framework) | a tokio TCP listener on the same three registered ports |

The OAuth client is the same public client the macOS app uses (its Client ID Metadata Document), so the
redirect URIs and ports are identical.

Closing the window while jobs run: the macOS app stays running with its Dock icon, which reopens the window. Here
the tray icon stands in for the Dock: while it shows (Settings › General › Show in the system tray, or tray mode)
the app stays running after the last job ends, as on macOS. With the icon off, outside tray mode, the window hides
while the work goes on and the app quits once the last job ends, unless the window was opened again: nothing would
be left to bring it back (`system::background::quits_when_work_ends`, `system/window.rs`, `events.rs`).

## On-device engines

The macOS app runs these with VideoToolbox, SpeechAnalyzer and Core ML. Here each is an open-source engine
behind the same port, offered with the same rules (one run at a time, consent before a model download, the
result as a new version of the item):

| Feature | Engine |
|---|---|
| Smooth Motion (60 fps, 2× and 4× slow motion) | ffmpeg `minterpolate`, with the same cut detection keeping a frame across a hard cut |
| Upscale 4× (video and image) | Real-ESRGAN ncnn-vulkan, binary and model downloaded after consent, checked by SHA-256 |
| Subtitles | whisper.cpp, model downloaded after consent; the cue builder, editor and SRT/VTT writers are ported unchanged |

## Phases

Each phase is implemented by one agent, checked by a second, independent reviewer, then committed.

1. Scaffold: workspace, crates, Tauri shell, React app, lints, checks.
2. `jutsu-core`; `higgsfield`; the design system and app shell.
3. `jutsu-providers`; `jutsu-store`; `jutsu-media` (probe, prepare, thumbnails, frames, audio, export).
4. `jutsu-engine`; `jutsu-agent`, `jutsu-mcp`, `jutsu-cli`.
5. `jutsu-app` and screens, one feature at a time: connection and onboarding; Create (video); Create (image),
   references, characters; Queue; Library (grid, details, culling, variants, history); Compare; Enhance;
   templates and prompt history; export for editing and delivery sets; Settings and spending; agents.
6. On-device engines; tray panel, notifications, background and autostart; updater; packaging.
